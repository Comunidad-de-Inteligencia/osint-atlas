# Accesibilidad de la documentación

La documentación se publica en Markdown dentro de GitHub. Se organiza por tarea, territorio e información disponible, con títulos descriptivos y recorridos de práctica.

## Comprobaciones automáticas

El validador comprueba un título principal, jerarquía de encabezados, enlaces internos y anclas, y texto alternativo no vacío cuando existe una imagen. Ignora los encabezados de bloques de código.

Esas pruebas detectan errores estructurales; no certifican accesibilidad ni sustituyen la lectura real.

## Comprobación de lectura

Para una entrega, recorrer README, catálogo, territorio, ficha y procedimiento. Confirmar que cada enlace permite anticipar el destino y que se entiende qué significa pendiente.

Repetir en una ventana estrecha equivalente a 320 píxeles CSS y con ampliación del navegador al 200 % y 400 %. Comprobar que el texto se adapta y que los controles esenciales siguen disponibles.

Recorrer los enlaces con Tab y activarlos con Enter. Comprobar foco visible y orden lógico. Si se usa un lector de pantalla, revisar la lista de encabezados y enlaces; registrar el dispositivo y el resultado.

El comportamiento de la interfaz general de GitHub depende de GitHub. Los hallazgos deben distinguir el contenido del proyecto de los controles de la plataforma.
